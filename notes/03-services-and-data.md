**Date:** 2026-08-10
**Status:** done — a customer can buy a shirt, `make test` proves it

## What runs

```
browser
  │ https://localhost/
  ▼
Istio gateway
  ├── /api/auth      ──▶ auth-svc      ──▶ MariaDB, Redis (sessions)
  ├── /api/products  ──▶ order-svc     ──▶ MariaDB
  ├── /api/orders    ──▶ order-svc     ──▶ MariaDB
  ├── /api/payments  ──▶ payment-svc   ──▶ order-svc, mock-payment, MariaDB
  ├── /dummy         ──▶ dummy
  └── /              ──▶ web-ui (Next.js)
```

| Namespace | What |
|---|---|
| `demo` | the six application services |
| `data` | MariaDB, Redis |

Data is in its own namespace so a NetworkPolicy can be written about namespaces
rather than having to name every pod.

## The purchase

Five requests, four services:

```
POST /api/auth/login            → token
GET  /api/products              → 6 shirts
POST /api/orders                → order, status pending
POST /api/payments              → payment-svc calls order-svc, the bank,
                                  then order-svc again
GET  /api/payments/:id/success  → status paid
```

`make test-checkout` runs it and then reads the `orders` and `payments` rows
directly. A handler can return 200 on a transaction that rolled back, so the
database is checked rather than the response believed.

## Credentials

Generated by `make secrets`, never in git:

| Secret | Where | Holds |
|---|---|---|
| `mariadb` | `data` | root password, app user and password |
| `app-secrets` | `demo` | the DSN built from the above, JWT signing key |

Created once and left alone. Regenerating on every run would change the
password out from under a database that still has the old one.

Schema and seed come from `storage/mariadb-init.sql`, applied by a Job.
Compose runs init SQL from the entrypoint; Kubernetes has no such hook. Every
statement is `IF NOT EXISTS` or `INSERT IGNORE`, so re-applying is safe.

## Tests

One file per usecase. `make test` runs them all, cheapest first.

| | Checks | What it would catch |
|---|---|---|
| `routing.sh` | 10 | a path reaching the wrong service, the catch-all shadowing the API |
| `auth.sh` | 10 | a wrong password being accepted, a missing session id |
| `checkout.sh` | 10 | the purchase breaking anywhere along the chain |
| `tls-proof.sh` | 4 | credentials travelling in plaintext |
| `resilience.sh` | 7 | data lost with a pod, requests dropped during a replacement |

`tests/lib.sh` holds the helpers so each file is about behaviour rather than
about counting passes.

## Two things that cost time

**Chart tags pinned to a version nothing builds.** The charts came in pinned to
`v0.4.0` while the Makefile builds `v0.1.0`. Helm installed happily, the
Deployment was created, and the pods sat in `ErrImageNeverPull` — `pullPolicy:
Never` means the kubelet does not even try, so there is no error until you look
at a pod. `platform/scripts/check-image-tags.sh` now compares them before any
image is built.

**A JSON payload written inline into a test assertion.** This:

```sh
expect "login" 200 "$(status POST /api/auth/login "{\"username\":\"$U\"...}")"
```

gets word-split on the comma, and curl receives two half-objects. The request
returns 400 and it reads as a broken service. Payloads go in a variable first.
Found with `bash -x`, which showed two `curl` calls where there should have
been one.
